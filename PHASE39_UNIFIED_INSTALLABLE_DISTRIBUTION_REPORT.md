# Phase 39 — Unified Installable Viskod Distribution Report

## 1. Executive summary

Phase 39 delivers one installable `@viskod/cli` product containing the CLI,
MCP runtime, and local Studio. `viskod studio` launches a package-local bundled
Studio outside a Viskod source checkout. The complete validation matrix is
PASS, including clean external installed workflow smoke, E2E, dogfood, CI,
release, package-content, lifecycle, and leak checks.

## 2. Distribution decision

One user-facing installation:

```bash
npm install -g @viskod/cli
viskod setup --project-root .
viskod studio --project-root .
viskod serve --project-root .
```

No separate Studio package, account, cloud service, telemetry, licensing,
subscription, or paid-plan gate was added.

## 3. Internal architecture

Studio remains modular under `apps/studio/src`. The CLI remains the public
entrypoint. Distribution contains two intentional runtime bundles:

- `dist/index.js` — CLI and MCP runtime.
- `dist/studio.js` — bundled Studio server, workflow, and server-rendered UI.

The CLI launches `dist/studio.js` with the installed Node executable. It does
not invoke `tsx`, workspace commands, or checkout paths.

## 4. `viskod studio` command

Supported command:

```text
viskod studio [--project-root <path>] [--url <app-url>] [--port <port>]
```

`viskod studio --help` returns help without starting Studio. The child process
inherits stdio and signals, uses the explicit project root as its working
boundary, and passes package-local runtime paths only.

`--url` validates and opens an HTTP(S) target through the managed browser;
`--port` configures the loopback Studio listener.

## 5. Studio packaging model

A dedicated second esbuild artifact is the smallest maintainable model. Both
bundles target Node 22 ESM and bundle workspace code. Native/runtime modules
`playwright`, `pngjs`, and `ws` remain external; `ws` is a direct runtime
dependency of `@viskod/cli`.

The UI is generated by the bundled Studio server (`renderStudioHtml()` and the
bundled overlay script). No filesystem UI asset is loaded from the checkout.

## 6. Package runtime manifest

Exact packed manifest:

```text
package/dist/index.js
package/dist/studio.js
package/package.json
```

No source TypeScript, tests, reports, `.viskod` state, feedback/review
artifacts, screenshots, `.env` files, or developer configuration files are
packed.

## 8. Trust/security preservation

checks, bounded request bodies, navigation policy, and controlled
`EADDRINUSE` handling remain unchanged. Existing security/lifecycle tests pass:
loopback binding, unauthorized-origin rejection, readiness ordering,
occupied-port cleanup, and idempotent shutdown.

The selection-event delegation guard prevents duplicate concurrent packet
capture when the Studio selection engine publishes a selection event and the
Studio workflow owns the following capture.
