# DEC-007: Desktop Shell Technology

**Date:** 2026-07-28
**Status:** Accepted
**Author:** Architecture
**Related Specifications:** SPEC-023 (studio)

## Context

SPEC-023 (Studio) requires a desktop shell to host the Studio UI. The architecture does not prescribe a specific technology — Studio is defined as "the primary graphical interface" with performance targets of <2s startup, <100ms panel switching.

The desktop shell must:
- Render a web-based UI (Studio is a React application per CLAUDE.md)
- Support keyboard navigation, screen readers, high-contrast themes
- Run on Windows, macOS, and Linux
- Integrate with the Node.js runtime (all subsystems run in the same process)
- Support local-first operation (no cloud requirement)

## Decision

**Electron** — the mature, cross-platform desktop shell with built-in Chromium integration.

Rationale:
- Electron is the most widely adopted desktop shell for developer tools (VS Code, Playwright Inspector, Postman)
- Chromium is already a dependency (Browser Runtime uses Playwright with Chromium). Electron bundles Chromium — no additional browser download.
- Electron's main process provides the Node.js runtime where all Viskod subsystems execute
- Electron's renderer process provides the web UI context for React
- IPC between main and renderer is built-in and stable
- Zero additional platform-specific packaging work (Electron-builder handles Windows/macOS/Linux)

## Alternatives Considered

**Option A: Tauri** — Rust-based, smaller binary, better memory usage.
- Advantages: 10-20MB binary vs 150MB+ for Electron; lower memory footprint; no bundled Chromium
- Disadvantages: Requires Rust toolchain (adds complexity to a TypeScript-only team); less mature ecosystem; Rust IPC bridge would need to wrap all subsystem interfaces; smaller plugin ecosystem
- Rejected because: Additional language dependency (Rust) conflicts with CLAUDE.md technology principles (TypeScript, React, Vite). Browser Runtime already requires Chromium/Playwright — Tauri would add a second browser engine.

**Option B: Native window (Node.js + system WebView)**
- Advantages: smallest binary, uses OS WebView
- Disadvantages: WebView behavior varies by OS (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux); inconsistent CSS/JS behavior across platforms; limited DevTools integration
- Rejected because: Architecture requires deterministic behavior. Cross-platform WebView inconsistencies violate Design Principle 4 (Determinism).

**Option C: Terminal-only (no desktop shell)**
- Advantages: simplest, smallest, no GUI dependencies
- Disadvantages: Cannot display screenshots, overlays, or visual context — the core product value
- Rejected because: The product vision is to "let AI see your UI." Studio is the human visual interface for that vision.

## Consequences

**Positive:**
- Single technology stack (TypeScript, Node.js, React, Electron)
- Chromium consistency (same engine for Browser Runtime inspection and Studio rendering)
- Mature packaging ecosystem (auto-update, code signing, installers)
- Large developer tool precedent (VS Code proves the model)

**Negative:**
- Larger install size (~150MB for Electron + Chromium)
- Higher baseline memory usage (~100MB for Electron main+renderer)
- Chromium version coupling: Studio's Electron Chromium must be compatible with Playwright's Chromium
