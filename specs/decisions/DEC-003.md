# DEC-003: Configuration File Format

**Date:** 2026-07-28
**Status:** Accepted
**Author:** Architecture
**Related Specification:** SPEC-004 (configuration)

## Context

SPEC-004 (configuration) needs a configuration file format for `.viskod/settings.json`. The format must support the configuration schema defined by SPEC-004, be editable by humans, and require zero additional dependencies.

## Decision

**Option A: JSON.**

The configuration file uses strict JSON — no comments, no trailing commas. The file is read with `fs.readFileSync` and parsed with `JSON.parse`. All configuration is validated against a Zod schema before use.

## Alternatives Considered

- **Option B (JSONC — JSON with comments):** Comments are valuable for inline documentation, especially in hand-edited configuration files. However, JSONC requires a comment-stripping preprocessor or a parser like `jsonc-parser`. This adds either a dependency or fragile custom parsing logic. The config schema is documented externally (in SPEC-004 and JSON Schema), so comments in the file itself are a nice-to-have, not a requirement. Migration path: adopting JSONC later is a superset change — any JSON file is valid JSONC, so backward compatibility is guaranteed.
- **Option C (YAML):** Human-friendly with comments, anchors, and multi-line strings. However, YAML parsers are large dependencies with a history of security vulnerabilities (schema-based deserialisation, the Norway problem). YAML's relaxed syntax makes validation errors harder to diagnose. The engineering standard explicitly prefers fewer dependencies.

## Consequences

- Zero dependencies for configuration parsing.
- Configuration is not editable with inline comments. Documentation lives in SPEC-004 and in a generated JSON Schema reference.
- Zod validation catches malformed configuration at startup with clear error messages.
- The config file is machine-writable by Studio UI without special comment-preservation logic.
- Migration to JSONC in a future phase requires only swapping the parser — the data model, Zod schema, and consumer code are unchanged.
