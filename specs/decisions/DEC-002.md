# DEC-002: Cross-Process Serialisation Format

**Date:** 2026-07-28
**Status:** Accepted
**Author:** Architecture
**Related Specification:** SPEC-002 (shared-types), SPEC-007 (event-bus)

## Context

SPEC-002 (shared-types) and SPEC-007 (event-bus) need a serialisation format for events and messages that cross process boundaries. The chosen format affects wire size, debuggability, schema enforcement overhead, and whether additional build steps or dependencies are required.

## Decision

**Option A: JSON.**

JSON is the canonical wire format for all cross-process messages in Phase 1. All message types defined by SPEC-002 are serialised to and from JSON. Validation and parsing use the built-in `JSON.parse` / `JSON.stringify` — no third-party serialisation library.

## Alternatives Considered

- **Option B (MessagePack via msgpackr):** 30–50% smaller payloads than JSON and faster encoding, but requires the `msgpackr` dependency. Binary payloads are not human-readable, complicating debugging and manual inspection. Adds a non-trivial maintenance burden for a saving that is irrelevant at Phase 1 data volumes. Migration path: if performance profiling in Phase 2 shows serialisation as a measurable bottleneck, the EventBus transport abstraction is designed to swap the serialisation layer without changing subscriber code.
- **Option C (Protocol Buffers):** Strongly typed, compact binary format, but requires a `protoc` build step, `.proto` files maintained in parallel with Zod schemas, and a protobuf runtime library. The dual-schema problem (Zod for runtime validation, `.proto` for wire format) creates a maintenance hazard. The engineering standard demands simplicity over speculative optimisation.

## Consequences

- Zero additional dependencies. Serialisation uses only Node.js standard library.
- All cross-process messages are human-readable in logs and debugging tools.
- No build step beyond TypeScript compilation.
- Parser overhead is negligible at Phase 1 throughput.
- Schema enforcement is handled exclusively by Zod validators defined in SPEC-002. The wire format is JSON, but the data shape is governed by typed, versioned Zod schemas — not by JSON Schema or an IDL.
- Migration to MessagePack in Phase 2 requires only: (1) add `msgpackr` dependency, (2) swap the serialiser in the EventBus transport layer. Subscriber code is unaffected.
