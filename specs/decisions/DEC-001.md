# DEC-001: TypeScript and Node.js Version Floor

**Date:** 2026-07-28
**Status:** Accepted
**Author:** Architecture
**Related Specification:** SPEC-001 (repository-layout), SPEC-002 (shared-types)

## Context

SPEC-001 (repository-layout) and SPEC-002 (shared-types) need concrete TypeScript and Node.js version targets to standardise tooling configuration across all packages. Without an explicit version floor, each package may drift to incompatible compiler targets, ESM/CJS module formats, or runtime APIs.

## Decision

**Option A: TypeScript 5.5+ and Node.js 22 LTS.**

- TypeScript 5.5+: enables `isolatedDeclarations` for per-file emit, improved ESM interop, and incremental build performance. The `erasableSyntaxOnly` flag prevents runtime-incompatible TypeScript features from entering the codebase.
- Node.js 22 LTS: V8 12.7 engine, active LTS support until October 2027. Ships with native ESM support, `node:test` runner, `node:sqlite`, and stable `fetch` / `WebSocket` / `URLPattern` globals.

## Alternatives Considered

- **Option B (TypeScript 5.0+ and Node.js 20 LTS):** Broader compatibility but misses `isolatedDeclarations`, `erasableSyntaxOnly`, and several ESM improvements. Node.js 20 enters maintenance in October 2025 and end-of-life in April 2026 — too early for a new project.
- **Option C (TypeScript latest and Node.js latest):** Access to newest features but unstable. Node.js odd-numbered releases are not LTS. Breaking changes between TypeScript minor versions create churn without compensating value for this project's scope.

## Consequences

- All packages ship as ESM (`"type": "module"` in `package.json`).
- `tsconfig.json` base sets `target: "ES2023"` and `module: "NodeNext"`.
- Node.js 22's `node:test` can serve as the baseline test runner before adopting Vitest.
- Contributors must run Node.js 22 LTS; engine pinning in `package.json` (`"engines": { "node": ">=22.0.0" }`) enforces this.
- Adoption of TypeScript 5.5+ `erasableSyntaxOnly` means `enum`, `namespace`, and `constructor parameter properties` are prohibited at the compiler level — aligning with the engineering standard of preferring explicit code.
