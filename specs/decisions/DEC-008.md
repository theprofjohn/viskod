# DEC-008: Phase 2 — Real Runtime Capture

> **Decision ID:** DEC-008
> **Date:** 2026-07-28
> **Status:** Approved
> **Affected Specifications:** SPEC-008 (browser-runtime), SPEC-010 (capture-pipeline), SPEC-014 (selection-engine), SPEC-012 (project-scanner), SPEC-015 (source-hint-engine), SPEC-023 (studio)

---

## Context

Phase 1 first vertical slice (commit `ff46b43`, tag `v0.1.0-first-slice`) delivered stub implementations of 8 packages running through pnpm workspace, Event Bus, and a basic Studio HTTP server. The "select an element → capture → display" flow works with mocked data.

Phase 2 must replace every stub with real implementations:

1. **Real Playwright-backed Browser Runtime** — `launch()`, `navigate()`, `captureScreenshot()`, `getDOMSnapshot()`, `getComputedStyles()` must call Playwright directly
2. **Selection Engine** — new package replacing simulated selection with real DOM resolution, hierarchy construction, and visibility evaluation
3. **File-backed Capture Pipeline** — replace in-memory `Map<string, CaptureMetadata>` with `.viskod/captures/{captureId}/metadata.json` and screenshot files
4. **Project Scanner** — new package detecting frameworks, routes, package managers, and build systems from the repository
5. **Source Hint Engine** — new package generating evidence-backed source file hints from DOM evidence and project metadata
6. **Studio polish** — real HTTP endpoints, proper selection workflow, Context Packet display

### New Package Creation

Each new package follows SPEC-001 conventions:

```
packages/selection-engine/
  package.json   — "@viskod/selection-engine"
  tsconfig.json  — extends ../../tsconfig.json
  src/
    index.ts     — public API barrel
    types.ts     — interfaces
```

### Architecture Rules (unchanged from baseline)

- **BR never imports VCE** — events flow: BR → EventBus → VCE
- **Studio never imports BR or CP directly** — command flow: Studio → VCE → BR
- **Selection Engine communicates via Event Bus** — publishes `SelectionChanged`, subscribes to `ViewportChanged`
- **Project Scanner is read-only** — never writes to project files
- **Source Hint Engine never reads source files** — only consumes Project Scanner metadata + DOM evidence

## Consequences

### Positive
- Remove all mock data from the vertical slice
- Real browser screenshots, real DOM snapshots, real computed styles
- Selection Engine provides validated, stable element references
- Project Scanner provides framework and route context
- Source Hint Engine provides evidence-backed file hints to AI agents
- Studio shows real context packets from real browser captures

### Negative
- Playwright dependency increases install time and disk usage (~200 MB for Chromium)
- Selection Engine adds coordination complexity with Overlay System
- Project Scanner adds startup latency (project scan before browser launch)
- Source Hint Engine adds processing to each capture (hint generation CPU cost)
- Integration testing complexity increases (need real browser, real project)

### Mitigations
- Playwright bundled Chromium reuses existing installation if present
- Selection Engine uses Event Bus for Overlay System communication (no direct coupling)
- Project Scanner runs once and caches results; incremental scans are fast (<200ms)
- Source Hint Engine caches results per route + element signature
- Integration tests use Playwright but with dedicated test HTML fixtures (not the developer's project)
